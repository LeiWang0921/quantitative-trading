# 项目结构说明

这份文档介绍项目里每个目录、每个文件的作用，以及每天的自动交易、回测、图表和研究分别是怎么一步步运行的。
策略规则的原理和回测结果见 [防守策略研究报告](防守策略研究报告.md)，常用命令见 [README](../README.md)。

## 1. 全貌

项目分三块，三块用的是同一套策略代码：

| 部分 | 做什么 | 入口 | 会不会下单 |
|---|---|---|---|
| 交易 | 每个交易日收盘后计算目标仓位，在盈透模拟账户下单 | `run.py`（Windows 计划任务每天自动调用） | 会 |
| 回测和图表 | 用历史数据检验 `config.toml` 里的当前规则 | `backtest.py`、`candidate_charts.py` | 不会 |
| 研究 | 比较各种防守做法，为规则提供证据 | `research.py`、`notebooks/` | 不会 |

整个项目最重要的设计是：**策略只做计算**。输入收盘价表，输出每个标的的目标权重（0~1），不连券商，也不下单；取数据和下单由 `broker` 负责。因此：

- `run.py`（模拟盘）、`backtest.py`（回测）、`candidate_charts.py`（图表）调用的是**同一个函数** `sleeves_core`，参数都来自 `config.toml`，模拟盘的决策和回测完全一致。
- 换券商只需要新写一个 `broker`，策略代码不用改。

> 注意：`autotrader/research/` 名字叫“研究”，但里面的 `strategies.py` 和 `data.py` 也被每天的交易使用。**改这两个文件会直接影响模拟盘的下单。**

模块之间的调用关系：

```
                          config.toml（所有参数）
                                │ autotrader/config.py 读取
        ┌───────────────────────┼─────────────────────────┐
     run.py                backtest.py              candidate_charts.py
        │                       │                         │
        │                       ├── research/engine.py（模拟成交）、metrics.py（评价指标）
        │                       │                         │
        └──── autotrader/strategy.py（把 config 参数整理成函数参数）
                     └── research/strategies.py: sleeves_core   ← 三者共用的策略计算
                              └── research/data.py（价格清洗、Market 数据结构）
        │
     run.py ── broker/ibkr.py ── ib_async ── IB Gateway（本机 4002 端口）── 盈透模拟账户
```

## 3. 每天的自动交易怎么运行

### 3.1 调用链

```
Windows 计划任务 “QuantTrading-DailyRun”（周一到周五 14:45，20:00 补跑一次；温哥华时间，美股收盘之后）
  └─ tools\daily_run.bat        切到项目目录，用 .venv 里的 Python 运行 daily_run.py
      └─ tools\daily_run.py     在 logs\scheduled_run.log 写一行时间 → 运行 run.py → 失败时弹窗
          └─ run.py             见 3.2
```

20:00 的补跑是为了应对 14:45 那次失败（例如 IB Gateway 没有登录）。同一天运行两次不会重复下单，因为 `run.py` 会把已提交、未成交的挂单算进持仓。

### 3.2 run.py 内部的九个步骤

| 步骤 | 函数 | 做什么 |
|---|---|---|
| 1. 连接券商 | `make_broker` | 按 `config.toml` 的 `mode` 选择 dryrun / paper / live。连上后检查账户号：mode 不是 live 却连到了实盘账户（账户号不以 D 开头），立即中止 |
| 2. 读参数 | `strategy.load` | 把 `[strategy]` 的共用参数和 `[strategy.sleeves]` 合并成一个字典 |
| 3. 取价格 | `latest_closes` | 12 只候选股、IEF、GLD，再加上 SPY（只用来判断逢跌加仓），各取最近 800 根复权日线（最长均线 300 日 + 500 日预热）；用 `clean_prices` 修正漏掉的拆股；如果美股还没收盘，去掉当天未完成的日线 |
| 4. 算目标权重 | `strategy.target_weights` → `sleeves_core` | 得到每个标的的目标占比，合计 ≤ 100%，其余是现金 |
| 5. 写信号日志 | `log_signal` | 每只股票的排名、趋势、波动、满额比例和目标（见 3.3） |
| 6. 清旧仓 | — | `exit_symbols` 里不属于当前策略的标的（例如切换策略前的 SPY），目标设为 0 |
| 7. 算可投资金 | — | 满仓 100% = 美元现金 + 这些标的的持仓市值，再留 2%（`cash_reserve`）不投 |
| 8. 算交易股数 | — | 目标股数 = 目标权重 × 可投资金 ÷ 收盘价，向下取整。挂单也计入持仓。只调整实际占比和目标相差超过 3 个百分点的标的（`rebalance_band`、`drift_only`） |
| 9. 下单 | `check_order`、`broker.market_order` | 先卖后买；买入金额不超过可用美元现金（不够就少买，下次运行再补）；每笔检查股数和金额上限（`[risk]`）；市价单，收盘后提交，下一个交易日开盘成交 |

加 `--no-trade` 运行时，第 9 步只打印“本应下单”，不真正下单。

### 3.3 怎么看日志

`logs/trader.log` 记录 `run.py` 每次运行的内容（包括手动运行）；`logs/scheduled_run.log` 记录每次计划任务的时间和完整输出，连接失败等报错也在这里。

下面是 2026-10-23 20:00 那次运行的日志（节选，省略了时间戳）：


逐段解释：

- **信号部分**：`满额比例 = 趋势 × min(1, 20% ÷ 近20日波动)`；`目标 = 10% × 满额比例`（入选时）。
  - **DIS 排第 2 却没入选**：7 个名额已经被原来持有的股票占满。
  - **GOOGL 排第 8 仍然入选**：它原来就在名单里，排名还在前 10（7 + 缓冲 3）以内，所以保留。
  - “原来持有哪几只”不是从账户读的，而是用价格历史从头逐日回放排名得到的（`select_top`）。所以不需要状态文件，回测和模拟盘的名单也完全一致。
- **防守部分**：IEF、GLD 都在自己的 200 日均线之下，所以那一份留作现金，现金占 56%。
- **账户部分**：`占比` 是当前持仓（含挂单）占策略资产的比例，`目标` 后面括号里是目标股数，`差` 是需要买卖的股数。
- **最后一行**：各标的的偏离都不超过 3 个百分点，所以今天不交易。例如 VZ 的目标是 2.9%，不到 3%，就不会从 0 开始建仓；JPM 只差 1.7 个百分点，也不调整。

## 4. 回测、图表和研究怎么运行

### 4.1 下载数据（前提）

| 脚本 | 需要 IB Gateway 吗 | 下载什么 | 存到 |
|---|---|---|---|
| `fetch_data.py` | 需要（只读连接，不会下单） | 默认：当前策略的全部标的 + SPY，25 年复权日线（研究用的 ETF 按 35 年） | `data/history/<代码>.csv` |
| `fetch_data.py --research` | 需要 | `[research]` 里的 15 只 ETF | 同上 |
| `fetch_data.py --universe` | 需要 | `universe.py` 里约 70 家公司，20 年，只取价格 | 同上 |
| `fetch_data.py AAPL MSFT` | 需要 | 只下载指定的标的 | 同上 |
| `fetch_macro.py` | 不需要 | FRED 的利率、失业等序列；旧金山联储新闻情绪；弗伦奇 1926 年以来的美股日收益 | `data/macro/` |

`data/history/*.csv` 的列是：`date, open, high, low, close, volume`（复权价格和成交量），再加上 `hist_vol`（历史波动率）和 `implied_vol`（期权隐含波动率），可以直接用 Excel 打开。

回测要用 `data/macro/DTB3.csv`（国库券利率）给现金计息，所以 `fetch_macro.py` 至少要运行过一次。

### 4.2 backtest.py：回测当前策略

```
data/history/*.csv
  └─ research/data.py: etf_market      对齐日期、修正拆股、算隔夜和日内收益、读国库券利率
      └─ research/strategies.py: sleeves_core   每天收盘后的目标权重（参数来自 strategy.sleeves_kwargs，和 run.py 完全相同）
          └─ research/engine.py: run            次日开盘成交、每成交 1 美元付 5 个基点成本、3% 再平衡阈值
              └─ research/metrics.py            年化收益、最大回撤、夏普、危机期间表现
                  → 打印表格；逐日净值存到 results/backtest_strategy.csv
```

对照组有两个：N 只候选股等额一直持有，以及 SPY 一直持有。回测起点会自动推迟：等防守资产和至少 7 只候选股都有了数据，再预热 500 天，均线信号才完整。

### 4.3 candidate_charts.py：候选股图表

它和 `backtest.py` 走同一条路线（`etf_market` → `sleeves_core` → `engine.run`），从 2004 年开始逐日模拟，但只画 2025-04-01 以后的部分。生成的文件：

- `docs/候选股票池.md`：每只候选股一节，按当前排名排序。
- `docs/candidate_charts/<代码>.png`：每只候选股和 IEF、GLD 各一张日 K 线图，蓝色阴影标出模拟持有的日子，颜色越深仓位越大。
- `docs/candidate_charts/_strategy_vs_SPY.png`：本策略和 SPY 的净值比较。
- `docs/candidate_charts/_long_term.png`：长期比较。

### 4.4 research.py：研究实验

`research.py` 由 11 个部分组成，可以全部运行，也可以只运行其中几个，例如 `research.py etf robust`：

| 部分 | 内容 | 输出 |
|---|---|---|
| `long` | 美国全市场 1927–2026（弗伦奇数据），只在股票和现金之间切换的各种做法 | `long_*.csv` |
| `bond` | 美国股票 + 合成的 10 年期国债，1963–2026 | `bond_*.csv` |
| `etf` | 可以实际交易的 SPY + IEF，2005–2026，次日开盘成交 | `etf_*.csv` |
| `markets` | QQQ / IWM / EFA / EEM，各自加 IEF | `markets_summary.csv` |
| `stocks` | 规则用于单只个股 | `stocks_*.csv` |
| `models` | 波动率预测、危机分类器、隐马尔可夫模型 | `models_*.csv` |
| `robust` | 参数敏感性、交易成本、成交时点 | `robust_*.csv` |
| `frontier` | 同样的最大回撤下，哪类做法收益最高 | `frontier_*.csv` |
| `news` | 新闻 / 调查类指标的检验 | `news_*.csv` |
| `economy` | 经济周期指标（失业率、申请失业金等）的检验 | `economy_*.csv` |
| `universe` | 约 70 家公司的客观数据 | `universe.csv`、`选股参考.md` |

所有输出都在 `results/research/` 里，`notebooks/defensive_research.ipynb` 读这些 CSV 画图。

`research.py` 记录的是 2026-10-20 的那轮研究，当时的研究对象是指数方案 `defensive_core`。之后关于个股方案的实验（排名、持有数量、均线权重、防守资产波动缩放、逢跌加仓等）用的是临时脚本，没有放进项目；这些实验的结论写在报告第 6 章。

## 5. 逐个文件说明

### 5.1 根目录

**`config.toml`**：唯一需要手动修改的配置文件。

| 段 | 内容 |
|---|---|
| `mode` | `dryrun`（本地假券商）/ `paper`（盈透模拟账户）/ `live`（实盘） |
| `[ibkr]` | IB Gateway 的地址、端口（模拟 4002，实盘 4001）、客户端编号 |
| `[strategy]` | `kind` 选择运行哪个策略（当前是 `"sleeves"`）；两个策略共用的参数：均线周期、均线缓冲、波动回看天数、现金保留、要清仓的旧持仓 |
| `[strategy.sleeves]` | ★ 当前方案的参数：候选股列表 `stocks`、持有数量、排名缓冲、个股份额 70%、波动目标 20%、均线权重、防守资产及其过滤、逢跌加仓阈值、再平衡阈值 |
| `[strategy.spy_ief]` | 之前的 SPY + 美债方案，参数保留，改 `kind` 就能切回 |
| `[backtest]` | 下载多少年数据、回测的交易成本 |
| `[risk]` | 实盘总开关 `allow_live`；单笔股数和金额上限 |
| `[research]` | 研究用的 ETF、FRED 序列、个别标的的交易所 |

**`run.py`**：每天的交易，见第 3 节。参数：`--no-trade` 只看决策不下单；`--reset` 清空 dryrun 的本地状态。

**`backtest.py`**：见 4.2。

**`candidate_charts.py`**：见 4.3。

**`fetch_data.py`**、**`fetch_macro.py`**：见 4.1。`fetch_data.py` 用的客户端编号是 `client_id + 20`，所以和正在运行的 `run.py` 不冲突。

**`research.py`**：见 4.4。

**`requirements.txt`**：`ib_async` 用来连接 IB Gateway；`pandas`（表格计算）、`matplotlib`（画图）、`ipykernel`（让 Jupyter 使用 .venv）、`statsmodels`、`scikit-learn`、`arch`（研究里的统计和机器学习模型）、`openpyxl`（读 Excel 格式的新闻情绪数据）。

### 5.2 autotrader/：交易用的核心模块

**`config.py`**
- `load_config()`：读取 `config.toml`。
- `ibkr_port(cfg)`：按 mode 选端口；mode 是 live 但 `allow_live = false` 时拒绝运行。
- `ROOT`、`DATA_DIR`、`HISTORY_DIR`、`MACRO_DIR`、`RESULTS_DIR`、`LOGS_DIR`：各目录的路径。

**`strategy.py`**：连接 `config.toml` 和策略函数的那一层。`run.py`、`backtest.py`、`candidate_charts.py`、`fetch_data.py` 都通过它读取策略参数。

| 函数 | 作用 |
|---|---|
| `load(cfg)` | 合并共用参数和当前策略的参数 |
| `symbols(params)` | 要交易的标的：候选股 + 防守资产 |
| `data_symbols(params)` | 要下载价格的标的：上面这些 + SPY（逢跌加仓的信号） |
| `exit_symbols(params)` | 要清仓的旧持仓 |
| `history_days(params)` | 需要多少根日线（800） |
| `max_holdings(params)`、`rank_buffer(params)` | 实际持有数量（7）；排名缓冲（`"auto"` = 候选数 ÷ 4） |
| `sleeves_kwargs(params)` | 把 config 参数转换成 `sleeves_core` 的参数。`run.py` 和 `backtest.py` 都用它，保证两边一致 |
| `target_weights(closes, params)` | 主入口：收盘价表 → (目标权重, 日志信息)。内部调用 `_sleeves`（当前方案）或 `_spy_ief`（旧方案） |

**`history.py`**：`save_bars` 把日线写成 `data/history/<代码>.csv`（`fetch_data.py` 使用）；`load_bars` 读回来。

### 5.3 autotrader/broker/：券商接口

**`base.py`**：定义 `Bar`（一根日线：日期、开高低收、成交量）和抽象类 `Broker`。每个券商都要实现这些方法：

| 方法 | 作用 |
|---|---|
| `connect()` / `disconnect()` | 连接 / 断开 |
| `cash(currency)` | 某个币种的现金余额 |
| `net_value()` | 账户净值及其币种 |
| `position(symbol)` | 当前持股数 |
| `pending(symbol)` | 已提交未成交的订单净股数（买为正，卖为负） |
| `history(symbol, days)` | 最近 days 天的复权日线 |
| `market_order(symbol, qty)` | 下市价单（qty > 0 买，< 0 卖） |
| `is_live` | 是否连到了实盘账户 |

**`ibkr.py`**：`IBKRBroker`，用 `ib_async` 库连接本机的 IB Gateway。
- 判断实盘：模拟账户号以 D 开头（如 DU1234567），否则就是实盘。
- `history()` 取 `ADJUSTED_LAST`（分红、拆股都已调整的价格）。
- `pending()` 会查询所有挂单，包括之前几次运行留下的。
- `adjusted_history()`、`daily_values()` 给 `fetch_data.py` 下载长历史和波动率用。
- IEF、TLT、SHY 指定 ARCA 交易所，才能取到 2002 年起的历史（在 `config.toml` 的 `[research] exchanges` 里设置）。

**`dryrun.py`**：`DryRunBroker`，不联网的假券商。用随机游走生成价格，起始资金 10 万 USD，状态存在 `data/dryrun_state.json`。每运行一次相当于过了一个交易日，订单按最新价立即成交。用来在没有账户时把整个流程跑通。

### 5.4 autotrader/research/：策略计算、回测和研究工具

**`strategies.py`**：所有策略函数。每个函数都返回一张“目标权重”表：行是日期，列是资产，值是收盘后希望持有的比例。

当前方案用到的函数：

| 函数 | 作用 |
|---|---|
| `trend_signal(close, n, band)` | 单条均线信号：价格高于 N 日均线 1% 以上为 1，低于 1% 以上为 0，中间保持原状态 |
| `trend_ensemble(close, windows, band, weights)` | 多条均线信号的加权平均，得到 0~1 的趋势信号 |
| `realized_vol` / `vol_weight` | 最近 20 日年化波动；`min(1, 目标波动 ÷ 实际波动)` |
| `trend_strength` | 价格高出均线多少（除以波动），排名相同时用来分先后 |
| `select_top(score, k, buffer, eligible)` | 每天选出前 k 名，带缓冲；不合格（满额比例为 0）的不选入、不受缓冲保护；逐日回放全部历史 |
| `dip_signal` | 逢跌加仓的触发条件 |
| `sleeves_core` | ★ 当前方案：把上面这些组合起来，输出每天的目标权重 |

旧方案：`defensive_core`（SPY + 国债的指数方案）、`economy_filter`（经济过滤）。

只用于研究对比：`buy_hold`、`static`、`sma_trend`、`monthly_sma`、`tsmom`、`vol_target`、`trend_vol`、`tipp`、`inverse_vol`、`gtaa`、`dual_momentum`、`risk_sleeves`。文件开头的注释逐一说明了它们是什么。

**`data.py`**
- `clean_prices`：修正盈透复权数据里漏掉的拆股（只检查 2005 年及以前），`REAL_MOVES` 列出了核实过的真实暴跌，这些日子不做修正。`run.py` 也用它。
- `load_etf`、`load_fred`、`load_french`：读取本地 CSV。
- `download_fred`：从 FRED 下载一个序列。
- `tbill_daily`：国库券利率换算成每天的现金收益。
- `synthetic_bond_returns`：用国债收益率合成 2004 年以前的国债回报。
- `Market`：回测用的数据结构，包含收盘收益、隔夜收益、日内收益、现金收益和收盘价。
- `etf_market`、`french_market`：从本地数据组装 `Market`。

**`engine.py`**：`run(target, market, ...)` 模拟按目标权重交易，返回每日收益、仓位、换手和各资产占比。
- `execution="next_open"`：收盘后算信号，第二天开盘成交，和模拟盘的实际做法一致。
- `band` / `drift_only`：再平衡阈值，规则和 `run.py` 相同。
- `cost_bps`：交易成本。现金按国库券利率计息。
- 不允许加杠杆或做空（权重必须 ≥ 0 且合计 ≤ 1）。

**`metrics.py`**：`summary`（年化收益、波动、夏普、最大回撤、Calmar、最长水下时间、平均仓位、换手等）；`crisis_returns`（`CRISES` 里 1929–2022 年 11 次主要下跌期间的收益）；`bootstrap_mdd`（用自助法估计未来 10 年最大回撤超过某个水平的概率）。

**`economy.py`**：`economy_good` 判断经济是否在转差，有失业率、申请失业金、萨姆指标、收益率曲线四种。只有 `kind = "spy_ief"` 时 `run.py` 和 `backtest.py` 才会使用；当前方案不用。

**`news.py`**：新闻情绪、政策不确定性、消费者信心等指标，按当时能看到的时间对齐。只用于 `research.py news`。

**`models.py`**：波动率预测（EWMA、GARCH、HAR）、危机分类器（逻辑回归、梯度提升树、神经网络）、隐马尔可夫模型。全部按年滚动训练，不使用未来数据。只用于 `research.py models`；结论是这些模型都没有超过简单指标，所以没有采用。

**`forecast.py`**：ARMA 收益率预测，`notebooks/arma_forecast.ipynb` 使用。结论是日收益率无法预测。

**`universe.py`**：`UNIVERSE`（约 50 家美国大公司，覆盖 11 个行业）和 `CHINA_UNIVERSE`（20 家在美国上市的中国公司），包括代码、中文名、行业和简介。`fetch_data.py --universe`、`research.py universe` 和 `candidate_charts.py`（取简介）使用。

## 6. 常见操作：改哪里、运行什么

| 想做的事 | 改哪里 | 然后运行 |
|---|---|---|
| 增减候选股 | `config.toml` 的 `stocks` | `fetch_data.py` → `backtest.py`（看结果）→ `candidate_charts.py`（更新图表） |
| 调整策略参数 | `config.toml` 的 `[strategy.sleeves]` | `backtest.py` 看效果；第二天计划任务自动按新参数运行 |
| 看今天会怎么交易，但不下单 | — | `run.py --no-trade` |
| 查看每天做了什么 | — | 打开 `logs/trader.log` |
| 自动运行失败了，查原因 | — | 打开 `logs/scheduled_run.log`（最常见的原因：IB Gateway 没登录，或实盘账户在别处登录导致错误 162） |
| 美元现金不够 | — | `tools/convert_fx.py <美元金额>` |
| 切回旧的 SPY + 美债方案 | `config.toml` 的 `kind = "spy_ief"` | `run.py --no-trade` 确认 |
| 暂停自动交易 | — | PowerShell：`Disable-ScheduledTask -TaskName QuantTrading-DailyRun` |
| 离线演练整个流程 | `mode = "dryrun"` | `run.py`（每运行一次 = 过一个交易日）；`run.py --reset` 重新开始 |
| 切到实盘 | `mode = "live"`、`allow_live = true`，并按实盘资金重新设置 `[risk]` 的两个上限 | 先 `run.py --no-trade` |

所有命令都在项目根目录用 `.venv\Scripts\python <脚本>` 运行，例如 `.venv\Scripts\python run.py --no-trade`。
